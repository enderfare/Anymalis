# Techniques

Techniques are learned, developed, or otherwise acquired methods for deliberately applying a character's capabilities.

A Technique represents **something a character knows how to do**.

Techniques are distinct from Traits, Skills, and Path abilities.

---

# Technique Principles

A Technique should describe a repeatable method rather than a broad category of competence.

A Technique may represent:

* A combat maneuver
* A specialized physical action
* A Resonance application
* A crafting method
* A movement technique
* A specialized sensory method
* A social technique
* A survival method
* A specialized use of a Skill
* A lineage-specific ability
* Another deliberate application of an existing capability

A Technique should not simply grant a vague bonus to being good at something.

---

# Technique and Skill

**Skills** represent broad learned capabilities.

**Techniques** represent specific applications of those capabilities.

For example:

> **Skill:** Athletics
> The character is trained in physical exertion, climbing, jumping, lifting, and related activities.

> **Technique:** Wall Runner
> The character has developed a specific method for maintaining momentum while moving across suitable vertical surfaces.

The Skill establishes the underlying competence.

The Technique establishes the specialized method.

A Technique may therefore depend upon a Skill without replacing it.

---

# Technique and Trait

**Traits** describe persistent characteristics.

**Techniques** describe deliberate applications.

For example:

> **Trait:** Resonant Hearing
> The character can perceive certain Resonance disturbances through sound.

> **Technique:** Resonance Echo
> The character deliberately focuses that perception to identify the direction of a disturbance.

The Trait provides the persistent capability.

The Technique provides the specialized application.

---

# Technique and Path Abilities

Path abilities are Techniques or abilities specifically associated with one of the Four Paths.

The Paths are:

* Scribe
* Channeler
* Artificer
* Null

A Path ability should remain distinct because its availability or progression is tied to a character's Path.

Not every Technique is a Path ability.

A character may possess Techniques from many sources regardless of Path.

---

# Technique Sources

Techniques may come from:

* Practice
* Instruction
* Lineage
* Lineage Specialization
* Background
* Path
* Specialized training
* Cultural tradition
* Resonance training
* Advancement
* Significant story events
* Other established character progression

The source of a Technique should be recorded when it affects availability or progression.

---

# Technique Structure

A Technique should normally contain:

```text id="jz0d0d"
Name
Source
Requirements
Action
Effect
Limitations
```

Not every Technique requires every field.

Simple Techniques may require only a description and effect.

Complex Techniques should define their requirements and limitations explicitly.

---

## Name

The name should communicate what the Technique actually does or represent the established terminology of the culture, Path, or discipline from which it originates.

---

## Source

Identify where the Technique comes from.

Examples:

* Lineage
* Scribe
* Channeler
* Artificer
* Null
* Training
* Background
* Specialized Instruction

Source does not necessarily determine power.

It determines context, availability, and identity.

---

## Requirements

Requirements define what must be true before the Technique can be used.

Possible requirements include:

* A particular Skill
* A particular Trait
* A Path
* A tool
* A material
* A Resonant Scar
* Access to Resonance
* A prepared Glyph
* A particular environment
* A specific state or condition

Requirements should only be included when they are necessary.

---

## Action

The Action describes what the character must deliberately do to use the Technique.

Examples include:

* Attempt a Skill action
* Spend an action
* Spend time preparing
* Manipulate a material
* Construct a Glyph
* Focus Resonance
* Perform a physical maneuver

The exact action economy belongs to the appropriate core rules.

A Technique should not introduce a new action system unless necessary.

---

## Effect

The Effect describes what happens when the Technique succeeds.

Effects should be:

* Specific
* Observable
* Consistent
* Mechanically interpretable

Avoid wording such as:

> "You become much better at fighting."

Prefer:

> "When you successfully use this Technique to reposition an opponent, you may move them to an adjacent suitable space."

The second version establishes a concrete interaction that can be adjudicated.

---

# Limitations

Techniques should clearly state meaningful limitations when required.

Possible limitations include:

* Range
* Duration
* Frequency
* Required conditions
* Required materials
* Environmental restrictions
* Target restrictions
* Resonance requirements
* Skill requirements
* Preparation requirements

Limitations prevent Techniques from becoming universal solutions.

---

# Technique Complexity

Techniques should be proportionate to the capability they represent.

A Technique should not contain several unrelated abilities simply because they share a theme.

If a proposed Technique:

* Grants multiple unrelated capabilities
* Replaces several Skills
* Provides broad unconditional bonuses
* Functions as an entire combat system
* Defines an entire character identity

then it should probably be divided or represented through another system.

---

# Resonance Techniques

Techniques may describe how a character deliberately manipulates Resonance.

A Resonance Technique does not automatically create a spell.

When a Technique produces a spell-like effect, it must interact with the established Magic System.

Relevant components may include:

```text
Element
Variant
Borders
Foundation
Conductor
Surface
Outlines
Spell Effect
```

A Technique may teach or permit a method of using these components, but it should not silently redefine the underlying rules of Glyphic Resonance.

---

# Elemental Affinity

A Technique does not grant Elemental Affinity merely because it uses an Element.

A character's natural Elemental Affinity comes from their **Resonant Scar** when applicable.

A Technique may require:

* A particular Element
* A particular Variant
* A specific Resonant Scar
* Access to a particular form of Resonance

Such requirements should be explicitly stated.

---

# Lineage Techniques

A Lineage may provide one Lineage Technique as part of its standard character package.

A Lineage Technique should represent a meaningful application of something associated with that lineage.

It should not turn the Lineage into a complete character class.

For example, a Sericari Lineage Technique might involve:

* Specialized silk manipulation
* Resonant Thread handling
* Living Loom interaction
* Silk-based movement
* A culturally developed craft method

The exact Technique depends on the Lineage.

---

# Technique Specialization

A Technique may be specialized through:

* Further training
* A Lineage Specialization
* Path development
* Advancement
* Story-based transformation

Specialization should deepen an existing capability rather than arbitrarily adding unrelated powers.

When a specialized Technique replaces or evolves an earlier Technique, the relationship should be recorded.

---

# Techniques and Advancement

Techniques fit naturally into the established advancement model:

```text
Practice
    ↓
Instruction
    ↓
Experience
    ↓
Mastery
    ↓
Transformation
```

A character may develop a Technique through repeated practice or formal instruction.

Experience may refine how the Technique is applied.

Mastery may produce a more reliable, efficient, or specialized version.

Transformation may fundamentally change the Technique when the character undergoes a meaningful change.

Advancement should not automatically grant new Techniques without an established reason.

---

# Technique Mastery

Mastery should represent improved understanding rather than simply larger numbers.

A mastered Technique may gain:

* Greater reliability
* Greater precision
* Reduced preparation
* Expanded application
* Improved efficiency
* Additional but related functionality
* Greater control over consequences

Mastery should preserve the identity of the original Technique.

---

# Technique Failure

A Technique should not assume automatic success unless its rules explicitly say so.

When a Technique requires a Skill check, contest, or other resolution, use the appropriate core resolution system.

Failure should follow the normal consequences of that resolution.

Techniques should not independently create contradictory failure systems.

---

# Technique Stacking

Multiple Techniques may interact.

They do not automatically stack when they produce the same effect.

When two Techniques appear to grant the same benefit:

1. Determine whether they produce distinct effects.
2. If distinct, both may apply.
3. If they overlap, apply the more specific rule.
4. If neither is more specific, use the normal system rule rather than multiplying identical effects.

A Technique should never create an unintended mechanical escalation through repeated wording alone.

---

# Technique Design Test

Before creating a Technique, ask:

### 1. Is this deliberate?

If the characteristic is always present, it may belong as a Trait.

### 2. Is this specific?

If the Technique can solve almost any problem in its category, it is probably too broad.

### 3. What existing system does it use?

Identify the relevant:

* Skill
* Attribute
* Trait
* Path
* Resonance rule
* Equipment
* Condition

### 4. What does the character actually do?

The Technique should describe a recognizable action or method.

### 5. What happens when it succeeds?

The effect should be concrete enough to resolve consistently.

### 6. What limits it?

If nothing meaningfully limits the Technique, examine whether it is too broad.

### 7. Does it create a new rule unnecessarily?

Prefer existing systems over bespoke mechanics.

---

# Standard Technique Format

Use this structure when creating a Technique:

```text id="h8r3cv"
# [Technique Name]

## Source
[Lineage / Path / Background / Training / Advancement / Other]

## Requirements
[Required Skills, Traits, Paths, materials, Resonance, etc.]

## Action
[What the character deliberately does.]

## Effect
[What happens.]

## Limitations
[Relevant boundaries, requirements, or restrictions.]
```

---

# Design Principle

A Technique should answer:

> **"What can this character deliberately do because they have learned, developed, inherited, or otherwise acquired this method?"**

It should not answer:

> "What is this character?"

That distinction belongs to Traits and Lineage.

It should not answer:

> "What broad capability has this character developed?"

That belongs primarily to Skills.
